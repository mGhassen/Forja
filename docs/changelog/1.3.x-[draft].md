# 1.3.x — Elblat

**Status:** draft  
**Since release:** 1.3.192 (`v1.3.192`)

User-facing changes for the next **1.3.x** patch. Update on every push; edit or remove bullets when later pushes correct earlier work. On ship, this file becomes `done/X.Y.Z-[released].md` (exact patch from the release tag) and a fresh `1.3.x-[draft].md` starts.

Use the [thematic groups](../../.cursor/rules/changelog.mdc#thematic-groups-forja) below — **add a `### Group` heading only when that group has bullets**; never leave empty group headers. Every bullet starts with `**Add:**` · `**Change:**` · `**Fix:**` · `**Remove:**`.

### Features
- **Add:** Settings → **LAN** — enable a desktop server, show a pairing code and paired TVs/phones; on TV/phone discover or enter IP once to trust that desktop for torrent playback.
- **Fix:** After pairing Android TV to a desktop, Settings → Playback shows Direct torrent / Stremio / Nuvio; turning them on brings back white Play and the Sources panel (playback via the desktop). If the desktop is offline, those sources stay off and locked until it comes back — previous checks restore automatically.
- **Change:** Desktop Settings → LAN shows this PC’s LAN IP(s) with the port next to the pairing code (copyable for manual TV pairing).
- **Add:** Desktop Settings → LAN **Paired devices** has a reload control to refresh the list after a TV pairs.
- **Add:** Settings → LAN on TV/phone has a reload control to re-check desktop online status (D-pad focusable on Android TV).
- **Add:** Desktop Settings → LAN **Torrent activity** — history of torrents opened by paired TVs, with live progress on the active row; delete one or clear all to free download cache.
- **Fix:** Desktop Settings → LAN **Torrent activity** no longer shows the same torrent twice (live status merged into the history row).
- **Fix:** Enabling LAN server on desktop no longer crashes or fails to start (duplicate `/health` route; Bonjour announce no longer blocks the HTTP server).
- **Fix:** Desktop LAN keeps the same listen port across app restarts (restores after torrent/proxy warm instead of racing boot); paired TVs rediscover if the address still changes — no re-pair.
- **Add:** Settings → LAN status dots — green when the desktop (TV) or a paired device (desktop) is online; grey when idle/offline.
- **Fix:** Paired TV/phone torrent play no longer fails immediately when the desktop LAN server resolves the magnet (nested engine panic).
- **Fix:** Leaving a LAN torrent on TV/phone stops the download on the desktop (cache stays until you delete it in Settings → LAN).

### UI
- **Add:** Search, Anime search, and Asian Drama search show an **X** on each recent query — tap (or TV: Right → OK) removes that saved search.
- **Change:** Settings → LAN puts Online/Idle (and desktop online/offline) on its own smaller line — not jammed into one dotted subtitle.
- **Fix:** On Android TV Settings, text fields (API keys, URLs, LAN IP, …) only open the keyboard after **OK** — D-pad focus highlights the field without typing mode.
- **Fix:** On Android TV Settings, opening the keyboard on a text field (e.g. LAN Desktop IP) scrolls the field above the on-screen keyboard.
- **Fix:** On Android TV, Home and details hero backdrops no longer Ken Burns pan/zoom (stills stay put; rotating art hard-cuts) so weak sets do not stutter.
- **Add:** Anime and Asian Drama hub heroes use the same Ken Burns backdrop pan/zoom as Home (desktop/mobile; stills on Android TV).
- **Fix:** On Android TV, leaving a page for the nav rail then pressing → returns focus to where you were (episode, card, …) instead of jumping back to Play.
- **Change:** Settings rows use the same green left-bar + tint hover/focus as the category rail (no bordered focus box).
- **Fix:** On Android TV, OK / → from a Settings category lands focus on the first right-pane control (not the empty detail scope).
- **Fix:** On Android TV Settings, focusing the first control (or any near the top) keeps the category title and section labels on screen — scroll snaps to the absolute top instead of pinning the control flush.

### TV
- **Fix:** On Android TV details, the hero **Trailer** / **Play** pills no longer clip their bottom edge under the hero margin when focused.

### Sources
- **Fix:** Videasy Sources lists every server (Yoru, Cypher, Breach, Neon, …) instead of a single sniffed stream — live API host + multi-mirror probe; if API fails, the player Servers dropdown is sniffed one by one.
- **Fix:** VidSrc.sbs Sources lists every top server (Pro Multi, Cinesrc, 4K, …) and rotates each mirror’s internal Servers chips instead of stopping after the first hit — Cinesrc `ice…/?m3u8=` proxy URLs count as playable again.
- **Fix:** VidRock Server List clicker only runs on VidRock embeds (no longer pokes “server” UI on VidSrc.sbs and other hosts).
- **Fix:** VSEmbed plays again when the old rcp/prorcp HTML path is gone — sniffs `vsembed.su` and force-starts the Play landing (`autoStart` off) so the real player + streams load.
- **Fix:** VidNest movie/TV streams open without a forced `vidnest.fun` Referer — CDNs that need no-referrer (and MovieBox) play again.
- **Fix:** VidLove / 111Movies play again when the site uses a signed `/api?…` media URL (MovieBox / VidAPI servers) instead of a bare `.m3u8` link.
- **Fix:** VidRock Sources can list multiple Servers (not only the default) by opening the Server List panel and rotating each server row during sniff.
- **Fix:** VidFast Sources capture streams again when the player uses opaque `/w/…` session URLs and bundled HLS.js (not only `window.Hls`), and rotate Server chips for multi-server.
- **Fix:** Vidzee sniff waits for Cloudflare clearance (when the challenge can clear) before collecting streams, and rotates servers like other embed hosts.

### Player
- **Fix:** On Android TV, Subtitle Settings Back closes the dialog only (no longer leaves the player); D-pad reaches text color and font chips.
- **Fix:** On Android TV, the torrent **Sources** panel (details and in-player) and torrent file picker take D-pad focus — tabs, providers, search, and the list; Back closes the panel.
- **Fix:** On Android TV, Sources search only opens the keyboard after **OK** — D-pad focus highlights the field without typing mode.
- **Fix:** In-app updates download the installer from the CDN `latest/` mirror (same as the website), not a versioned archive path that could miss a split-arch build.

### Live & IPTV
- **Change:** Settings → Playback has separate **Movies & series engine** and **IPTV engine** on Android — IPTV Movies/Series follow Movies; live channels follow IPTV (no longer forced MediaKit / shared inherit).
- **Fix:** Android TV IPTV movies/series on ExoPlayer show the progress scrubber again (same as MediaKit).
- **Add:** IPTV ExoPlayer shows the same top-right **stream stats** control as MediaKit (tracks, bitrate, buffer).
- **Change:** IPTV Movies/Series player chrome is back — **Audio** / **Subs** (+ **Episodes** on series) sit on the right of the bar; Live stays without those track buttons.
- **Change:** On Android TV IPTV, ↓ from Live/Movies/Series (and catalog open) lands on the first pinned group when any are pinned — otherwise the first portal category (not Favorites), without scrolling that row to the top of the rail.
- **Change:** IPTV movies and series open as a Home-style details overlay — same D-pad/scroll as movie details (Play first, ↑ scrolls the hero back into view, Cast/Crew/Trailers/Recommendations; series also get season/episode cards).
- **Add:** Settings → Playback → **IPTV live recovery** option **Stable — reopen on buffer stall (test)** — same buffer-aware hold as 1.3.170, but reconnects when buffering/freeze stalls with no playhead (MediaKit).
- **Add:** Android TV Settings → Playback → **IPTV match display refresh** (off by default) — turn on to test MediaKit matching the TV refresh to the channel fps (e.g. 50 Hz for 50 fps).
- **Change:** Desktop IPTV category drag-reorder uses the same brighter-green rail highlight as Android TV (no floating card).
- **Fix:** Android TV category reorder (hold OK) keeps focus on the floating group and moves **one** category per ↑/↓; when pinned at the second visible slot the rail scrolls in lockstep (no flash).
- **Fix:** On Android TV, leaving Forja for Home while a live match or IPTV channel is playing pauses audio; returning resumes where you left off (desktop can still keep playing in the background).
- **Fix:** On Android TV, opening the IPTV **Portals** panel puts D-pad focus on the selected portal (Add only when the list is empty).
- **Fix:** On Android TV, IPTV live channel status is checked only after staying on a channel for **350ms** — skimming with ↑/↓ no longer probes every row.
- **Change:** On Android TV, IPTV catalog and in-player channel guide logos load after D-pad focus is idle **500ms**; logos already on screen stay while you scroll — only newly revealed channels wait for the next idle settle.
- **Change:** Android TV category pin stays hidden while browsing — normal → opens channels; hold OK ~1s reveals the pin (and reorder) so → can focus it; OK on the pin no longer jumps the sidebar scroll.
- **Fix:** On Android TV IPTV, after pinning or reordering a category, OK / → opens that group’s channels again (no longer stuck on the category rail).
- **Change:** Android TV Live Matches cards are landscape tiles (16:9 art + title under) — not square/portrait IPTV poster cells.
