# Player

> One player for movies, series, IPTV, and more — desktop and mobile.

## What it is

Forja routes all video playback through a unified player. Controls use a flat overlay (no glass chrome):

- **Top bar** — back arrow (muted until hover or D-pad focus, then white), centered title, **S# E#** for TV episodes, and **Player**, **Cast**, and **PiP** on the top right (platform-gated; Android TV shows **Player** only)
- **Paused overlay** — show logo, rating/year meta, and synopsis on the left when playback is paused (when TMDB metadata is available)
- **Center actions** — large play/pause and ±10s buttons in the middle while controls are visible; hidden while checking sources or buffering (status roulette takes the center instead)
- **Status roulette** — center-right slide-up indicator when checking sources, switching servers, or buffering (no bottom snackbars). Episode switches and mid-playback torrent/magnet switches use a separate bottom-right loading card instead (current video keeps playing until the new stream is ready). If every source fails, the detailed failure and Retry / Stream actions appear once under the centered title
- **Episode switch card** — compact translucent card at bottom-right above the seek bar (no border, no full-screen dim) when picking another episode, Next/Previous, or another torrent/magnet: label plus live status (`Loading episode info…`, `Checking sources…`, `Starting Local Torrent Engine…`, `Opening stream…`). Video stays visible behind it until the new stream is ready
- **Bottom bar** — full-width seek bar, then play/pause, ±10s, previous/next episode when available, volume, and **current / total** time on the left; **Sources** (link/magnet icon — torrent / Stremio / Nuvio catalog panel when playing a magnet **or** a Stremio Direct / Nuvio stream; same as media-details Sources, including the **Nuvio** kind chip when Direct torrent scrapers are enabled). While Sources is available for that session the flat **Source** server picker (layers + name + chevron) stays hidden so catalog playback is not duplicated as a “server”. **Source** appears only for web/anime/drama streams. Then episodes (TV), audio, subtitles, quality, settings, and fullscreen on the right. On desktop torrent playback, when **Settings → Torrent stats** is on, a transparent stats card sits bottom-right above the seek bar while controls are visible (download/upload speed, peers, download size/%, ETA). It lifts above Skip Intro / Next Episode when those buttons are showing. Seeders show as — unless indexer metadata is available later — librqbit does not expose a live seeder count.
- **Floating menus** — audio, subtitles, quality, servers, player, and settings open as compact popup panels anchored to the button you tapped (above or below, depending on space). Menus use a flat dark shell with **brand-green** selected chips (green fill / dark text) and green-tinted list selection. Options sit **directly under the panel header** (icon + title + close) — no nested cards. **Quality** is a row of segmented chips; **Audio** and **Servers** are full-width chips; **Player** lists full-width chips under muted **Built-in** / **External app** labels (on **Android TV**, **Player** lists only **ExoPlayer** and **MediaKit** — no external apps). **Subtitles** shows **Off** and **File** (load from file — hidden on Android TV) in the header, then one drill-in row per language (count = in-stream + online). **Settings** is a drill-in list — each parameter (Auto selection, Video decode, Playback speed, Aspect ratio, Loop, and Torrent stats on desktop torrent) is a row with its current value; tapping opens that parameter's own second page showing just its chips under the header. Subtitle style lives in the **Subtitles** menu (tune icon in its header), not in Settings. The **Back** control (muted until hover or D-pad focus, then white) returns to the parent list. Dismiss with the outlined square **Close** control in the menu header
- **Episodes / Sources / Source panels** — TV **Episodes**, torrent **Sources** (magnet button), and web **Source** (server picker) open right-side panels. Player **Episodes**, **Sources**, **Source**, and **Filters** use a translucent dark shell (no freeze-frame image; no BackdropFilter over live video). **Filters** opens docked to the left of Sources only when you tap the tune control (Filters only covers the area left of Sources so source rows stay tappable); closing Sources dismisses Filters. **Source** lists servers with status glyphs — tap a server to load its streams in parallel. Selected and currently **playing** rows use the same brand-green accent as floating menus. The **Episodes** top bar has a brand-green **Season** pill (when the show has multiple seasons), a combined **Search** field + **Auto next** switch (skip-next icon), and a squared **Close** control. A range dropdown (**1 - 50**, **51 - 100**, …) appears below when the list is long. Episode rows show thumbnails, air date (orange when not yet aired), show backdrop with dim overlay on not-yet-aired thumbnails, runtime, synopsis, and resume progress. Not-yet-aired episodes stay visible but cannot be opened.

Seek bar uses Forja brand green for the played fill and thumb across the main player, trailer player, ExoPlayer chrome, IPTV VOD, music, and audiobook players. On desktop the thumb stays on the playhead; hover shows a timestamp (and a current-frame thumbnail when available — preview never seeks) and a click on the bar seeks. HLS/embed servers (e.g. VixSrc) confirm play once a video frame is up; the timeline fills in when duration arrives (close the **Source** panel to scrub — open menus ignore seek taps). **Source** is one flat bottom-right control showing the active server name; tap it for the grouped list. The player handles torrent streams, direct HLS/MP4 links, debrid URLs, Jellyfin, and hub content.

On **Android**, when the **movies/series** engine (Settings → Playback → **Movies & series engine**, or that player’s **Player** menu) is **ExoPlayer**, the same flat overlay chrome applies (top bar, paused hero, center actions, status roulette, bottom seek bar). **Sources** opens a **two-column** dialog (left = servers, right = streams for the selected server — check a server to load/probe its streams, then pick a stream to play). On **Android TV**, focus stays on the server you checked (it does not jump to Close), and focused rows use a brand-green border/fill. **Subtitles** opens the same kind of **two-column** dialog (left = languages; right = in-stream + online tracks). **Off** / **File** sit in the header (**File** hidden on Android TV). D-pad **←/→** moves between columns; **↑/↓** stay inside the focused column. **Episodes** (hub or TMDB), **Audio**, **Quality**, lean **Settings** (speed + fit), and **Player** open floating popup panels. Picking a subtitle language or file downloads/applies it without leaving playback. Subtitle appearance (tune) and ASS stay on MediaKit. **PiP** and **Cast** are hidden on Exo. Seek preview, torrent localhost, the catalog link **Sources** panel, and a separate audio URL still need **MediaKit**. On **phone**, ExoPlayer draws through a TextureView so the Flutter embed stays a single coherent frame. On **Android TV**, **Home / movies / series** ExoPlayer always uses TextureView (SurfaceView went sound-with-black-picture on physical sets). **IPTV live** Exo also uses TextureView on Android TV: SurfaceView played sound with a black picture (even on a fresh open) and could hide the player chrome on some sets. TextureView Exo live often feels soft / low-FPS on leanback — **Android TV IPTV defaults to MediaKit** for that reason; pick Exo from **Player** only if you need it. The TV emulator always uses TextureView. Because TextureView cannot hand the display a frame-rate hint, **Android TV movies/series ask the set to switch to a refresh rate that matches the film** (e.g. 24 fps content moves off a 60 Hz mode, where it would otherwise judder on every pan). The switch is skipped when the current refresh already divides cleanly (30 / 60 fps content), when the TV exposes no matching mode at that resolution, or when the stream does not report its frame rate — and the set returns to its normal mode when you leave the player. On **Android TV**, seeking in a movie also snaps to the nearest keyframe **before** your target, so ±10s on the remote responds immediately without ever skipping past unwatched footage. Switching **Player** from MediaKit to ExoPlayer briefly shows **Switching player…** while MediaKit fully releases, then Exo letterboxes correctly (no zoomed crop). **IPTV live** on Android uses Settings → Playback → **IPTV engine** (independent of Movies); with Exo it keeps a deeper live buffer and full portal quality unless you set **IPTV live max quality**. IPTV Movies/Series follow **Movies & series engine**.

On **Android TV**, **MediaKit** uses **MediaCodec embed** output (`vo=mediacodec_embed`) with Flutter Impeller disabled at boot (Skia via app shell args — the manifest does not force Impeller on) so frames hit the Flutter surface without mpv OpenGL — Impeller + `vo=gpu` was audio-only / black on leanback (and ATV emulators hit `EGL_BAD_ATTRIBUTE`). Phones keep Impeller (Flutter default on API 29+); phone MediaKit still prefers software decode when you pick MediaKit over Exo. On **IPTV live**, MediaKit matches display refresh for HD/FHD **and 4K** (same path that played 4K before v1.3.81), stays on MediaCodec (no software-decode fallback — that force-closed leanback on UHD), and keeps the Android audio output attached after open. **ExoPlayer** IPTV live keeps edge speed catch-up on HD/FHD and disables it on **4K** so audio does not stutter. On Android TV, **ExoPlayer** asks the set for a refresh rate that divides cleanly into the content frame rate — so 50/25 fps channels stop juddering on a fixed 60 Hz panel. **IPTV MediaKit** does the same only when **Settings → Playback → IPTV match display refresh** is on (off by default). The switch happens once per open (never mid-channel) and is skipped when the current mode already matches; the TV returns to its own mode when you leave the player. Switching **ExoPlayer ↔ MediaKit** from any **Player** menu (movies, series, anime, drama, IPTV, Live) unmounts the current surface, cools down briefly, then starts the other engine (avoids an Android TV force-close mid-switch).

On **Android TV** (MediaKit or ExoPlayer), when chrome is visible D-pad moves focus to the **nearest control in that direction** (spatial — top bar ↔ progress bar ↔ transport, and ←/→ among neighbors on the same band). The **bottom transport row** wires explicit neighbours on both engines — including the **Source** picker — so **←/→** walks every control (play/pause, ±10s, prev/next episode, Sources, Source, Episodes, audio, subtitles, quality, settings) and **↑** from any of them returns to the progress bar. **←/→** never skip ±10s while a chrome button is focused (seeking is on the **progress bar** after **OK** arms scrub, or via **←/→** when chrome is hidden). Layout: **back** and top-right **Player** (ExoPlayer / MediaKit switch — external apps, Cast, and PiP are hidden on TV; **MediaKit** is the default), then the **progress bar**, then the bottom transport row split like desktop — **play/pause**, ±10s, and previous/next episode when available on the left (no volume or lock chrome — use the remote’s hardware volume keys); **Sources**, **Source**, **Episodes**, audio, subtitles, quality, and settings on the right — then **Skip Intro** / **Next Episode** when shown. When every stream fails, the top-center **Retry** / **Stream** actions sit between **Back** and **Player**. **IPTV** on TV uses the same green focus chrome and FocusNode D-pad path as the movie player for **Back**, top-right **Player** / source / stats, and the bottom transport row (focus lands on **Play** after open; **←/→** on transport uses explicit edges so the remote is not trapped — including after Live Matches Streamed/PPV handoff when an embed WebView stays mounted underneath for CDN fetches); **stream stats** opens with D-pad focus on **Close**. Trailer chrome on TV matches the same split: play / ±10s left (no volume — use hardware volume), subtitles / quality / speed right; no large center play/skip buttons; chrome auto-hides after **10 seconds** idle while playing (D-pad activity resets the timer); remote **Back** focuses the top-left **Back** control first (showing chrome if needed — same ladder as the film player); **Back** again leaves the trailer; remote **Exit** is separate (double-confirm quit); top-right **Player** opens a menu to stay in Forja or hand off to the **YouTube** app; when there are multiple trailers, a **More videos** card sits bottom-right (**←/→** slides previews, **OK** plays, **↑** focuses Back, **↓** focuses the progress bar). The focused control turns **green** (icon, soft fill, outline) with no scale lift. On the progress bar: focus alone does not seek — **OK** arms the thumb, then **←/→** nudge the preview, **OK** commits (**Back** cancels); unarmed **←/→** leave the bar to **Play** (left) or the right transport cluster (**Sources** / **Source** / …). **↑** from the bar focuses **Next Episode** or **Skip Intro** when those chips are showing, otherwise the top **back** control. Hardware **volume** keys adjust player volume even while chrome is focused; when chrome is hidden (or focus is on the video, not a control), D-pad **←/→** seek ±10s, **↑** focuses **Back**, and **↓** focuses **Play** (showing chrome if needed). Audio, subtitles, quality, settings, episodes, and **Source** menus or panels take D-pad focus when opened (shared overlay focus host — focus lands on the **currently selected** option when there is one, otherwise the first; **↑/↓/←/→** move to the nearest option on screen inside the menu only — not the player chrome; focused row uses a gray fill + thin border with no scale; **OK** picks; **Back** closes and returns focus to the chrome button that opened the menu). **Subtitle settings** (from the subtitles menu) is a D-pad focusable dialog — **OK** on a slider arms it, then **←/→** nudge (**OK** commits, **Back** cancels); color / font chips, delay ±, and Bold need **OK** to change; **Back** closes the dialog when nothing is armed (then focus returns to the Subtitles button). App **toasts** (top-right status messages) expose focusable **action** and **dismiss** controls on TV. **Episodes** on TV opens focused on the **playing** episode; **↑/↓** moves between episode rows (**OK** plays); **↑** from the first episode focuses **Season** (when shown) or **Search**; **OK** on Season opens the season menu; **→** from Season reaches **Search** (browse focus — keyboard only after **OK**), then **Auto next**, then **Close**; **↓** from Season / Auto next / Close returns to the episode list; from **Search**, **OK** / Done / **↓** focuses the **first** matching episode (does not play it) — **↑/↓** then move through results and **OK** on a row plays it. **Sources** and **Source** side panels are D-pad focusable (close, season/range chips, list rows). **Back** (remote or the top-left back control) closes an open menu, panel, subtitle settings dialog, or toast focus target first; the next **Back** focuses the top-left **Back** control (showing chrome if it was hidden); **Back** again leaves the player. After leaving, **Back** steps through the screen under the player (details Back → catalog, or IPTV channel → category → nav rail). Controls auto-hide after **10 seconds** of idle while playing (D-pad activity resets the timer even while focus is on a chrome button; hide is deferred while a chrome control still has focus; paused keeps chrome visible).

## How to open it

Tap **Play** on any details screen, stream list, IPTV channel, or hub episode.

On desktop and Android TV, playback opens in a **full-window layer** above the app shell — the left nav rail stays mounted under that layer (same lifecycle as the screen under the player). **IPTV** is the exception: its player opens in the shell overlay and hides the rail Offstage for full-width video (rail Element kept alive so exit does not remount). Opening any fullscreen player (movie, trailer, IPTV, Live Matches handoff) also clears poster/image memory and unloads other shell tabs so decode gets max resources — the screen under the player stays mounted for a fast Back. On **Android TV**, those opens are an instant cut (no slide) so the set does not stutter while the player starts.

## What you can do

- Play, pause, seek (click the bar; hover preview on desktop when supported), and adjust volume (hover the volume icon to expand the slider — main player and trailer on phone/desktop; on Android TV movie / anime / drama and IPTV there is no chrome volume button — use hardware / system volume). On Android TV the **MediaKit** engine is boosted so it plays at about the same loudness as **ExoPlayer** — switching engines should not force you to change the TV volume. After a title ends, the progress bar still moves — click back on the bar or restart from the beginning without reopening the player
- Double-click the video (desktop) to enter/exit fullscreen — films also support **F** or the fullscreen button; trailers use the fullscreen button or double-click; IPTV / Live Matches use the fullscreen button or double-click on phone/desktop (hidden on Android TV)
- Back / Escape exits the player and **stops audio** immediately (mpv/Exo are stopped before the route closes). On desktop, the mouse **Back** side button and a two-finger trackpad swipe-right on page chrome (left-edge arrow fills to commit) do the same as the player Back control. Leaving returns to **details** (movies/TV, Anime, Asian Drama) — the stream-loading overlay is stripped under the player before the pop so Back never flashes resolve UI. On **Android TV**, D-pad focus returns to details **Play** / **Resume** when nothing else on the page is focused. Leaving the player also **stops background source checks** for that session (server probes, Nuvio scrapers, embeds). Leaving media details — or switching shell tabs while the loading screen is still checking servers — stops torrent / Stremio / Nuvio / webstreaming fetches for that title so they do not keep running in the background.
- Switching to another app (Home, Netflix, app switcher) **pauses** VOD, IPTV, and Live Matches on **phone and Android TV** so Forja does not keep playing under the other app — the process stays warm for a quick return. Returning to Forja resumes if it was playing when you left. On **Android TV** this pause is always on (no Settings toggle). On **desktop**, playback **keeps going** by default when the window leaves the foreground; toggle **Settings → Playback → Play in background** on desktop/phone to change that. **PiP** (phone/desktop) keeps playing while the floating window is active. On desktop, **Auto picture-in-picture** (same Settings page, off by default) can enter PiP on Space / virtual-desktop switch instead of pausing.
- Skip ±10 seconds from the bottom bar or large center controls. For series / anime / drama, previous and next episode buttons also appear in the bottom bar when an adjacent episode is available (±10s stay visible too).
- Open **Source** (bottom right) — a right-side panel with server rows and stream lists underneath. Headless WebView sniffs load embed URLs inside an iframe by default (some providers still force a direct load). Stream rows append a language **flag** when the title includes a flag emoji or a recognizable language (e.g. `🔗 CloudStream Pro from VidSrc 🇩🇪`). Tap an empty server to **check** it (loads its stream list). Tap a loaded server to **expand/collapse** its streams. Hover a loaded server (or D-pad focus it on Android TV, then **→**) to show/reach a **reload** icon beside the name (drops the Play cache for this title and refetches that server from the network). When a server returns **multiple streams**, the panel lists every row first, then probes them **one by one** (server subtitle shows `Checking 2/5…`; each row shows Checking → ready/failed). Tap a stream row to re-check it anytime (probe does not interrupt playback). Playing rows stay on the **catalog** URL even when playback goes through the local PNG-strip proxy — checking another server does not hide or replace the active stream row. **Playing** is scoped to the active server — the same CDN URL under another server stays a playable row (not a blue pause on the wrong host). Each server also shows a **score badge**: the **number is the provider’s running Σ** across titles (count **up or down**, never below **0**); the **+/− prefixes** are this film/episode’s server and stream verdicts only (Asian drama not scored). Per-title outcomes update Σ by their delta (a title at **−2 −2** drops Σ by 4, floored at 0 — fails while already at 0 stay at 0). Title score is the **net** of two **linked** verdicts committed together when the check finishes: extract OK + stream OK → **+2 +2**; extract OK + all streams dead → **+2 −2** (net 0); extract empty → server **−2**. Cancel / mid-check / extract-only does **not** leave a lone server **+2**. Stream **−2** only when every known stream is dead — not on the first miss. So an up server whose streams are all dead nets **+2 − 2 = 0**, an up server with a working stream nets **+4**, and a server that never resolved nets **−2** or **−4**. A **+/− prefix** shows this title’s verdicts; re-checking the same title re-evaluates them instead of drifting. Server dots: **green** = up (streams listed / extract succeeded), **gray** = not checked yet, **red** = failed. Playing is **Playing now** / the stream pause control — not the server dot. **CHECKING SOURCES** / Auto tries servers in order until one works for open. If you **manually** check or pick a server/stream, a fail **stops** — no auto hop. Tap an unloaded server to fetch its streams. Hover a live stream to reveal the **play** arrow and switch; failed streams never show play.
- When you leave the player and press **Play** again for the same movie or episode in the same session, Forja reopens the last working web stream directly on that server — no full provider recheck. If you switched server or quality in the player, that selection is remembered.
- First-time search checks providers one at a time in your settings order until one works; after that, playback stays on the server that worked unless you turn **Auto server** back on in player settings.
- Open **Episodes** from the bottom bar — a right-side panel lists the season’s episodes with thumbnail, title, air date (orange when not yet aired), runtime, and synopsis. The top bar has a brand-green **Season** pill when the show has multiple seasons, **Search** to filter by title or episode number, and an **Auto next** switch (same preference as Settings → Playback → Auto next episode). Use the range dropdown under the top bar when there are more than 50 episodes. Picking an aired episode closes the panel and shows a compact translucent loading card at bottom-right above the seek bar (`Season X · Episode Y`) with live status (`Loading episode info…`, `Checking sources…`, provider name while checking, `Opening stream…`) while Forja resolves the stream and reloads in-player; not-yet-aired episodes do not launch playback. The same card appears for Next/Previous episode
- Pick another torrent, Stremio, or Nuvio stream from the player **Sources** panel — the panel opens on **Torrents** when available (else Nuvio, then Stremio), loads only that kind, keeps results for about 30 minutes, and shows **reload** on the selected category tab only. Switching away from a kind while it is still loading stops that fetch. Provider chips (indexers, Stremio addons, Nuvio scrapers) sit under the kind tabs. Torrents and Stremio show their complete fetched response; Nuvio loads a scraper when you tap its chip (tap again clears its rows); more selected scrapers load lazily one at a time. It closes immediately after a pick, and the CHECKING SOURCES roulette shows while the magnet/stream resolves. Reopening **Sources** borders the currently playing torrent/stream and scrolls it into view.
- On **Android TV**, holding **↑/↓** in the player **Sources** list speeds up the further you hold
- Switch **audio**, **subtitles**, and **quality** from dedicated bottom-bar buttons
- Open **Settings** popup for auto selection, **Auto skip intro**, speed, aspect ratio, loop, and hardware decode — a drill-in list where each parameter opens its own second page with On/Off or value chips (same brand-green chrome as other floating menus). Subtitle style is reached from the **Subtitles** menu header (tune icon). On desktop torrent sessions, toggle **Torrent stats** (off by default) to show live download/peer info above the seek bar while controls are visible
- Use picture-in-picture on Android and desktop
- Tap **Cast** on supported platforms (AirPlay on macOS/iOS, Chromecast on Android/iOS/Windows). Native casting is not wired yet — the player shows a status message (e.g. “AirPlay is not available yet”) instead of failing silently
- Skip intro/recap/credits when IntroDB has data (optional **Auto skip intro** in Settings → Playback or the player Settings menu for intro/recap)
- Jump to next episode for TV content (optional **Auto next episode** — Settings or Episodes panel switch). Auto next only runs after a real watch reaches the end — a torrent that fails to start (or EOFs before video) does not skip ahead
- Launch an external player instead of built-in (Settings)

## Tips

- If a **cached** stream list is dead (open/check fails), Forja drops that cache immediately and tries the other URLs from the list — with **Auto server** On it then re-searches servers from scratch like the first Play. Manual **reload** / **check** never reuse the saved Play cache. If you **pinned** a server (or Auto server is Off), it refreshes that server only and stops so you can pick another from **Source**. **While you are already watching**, a mid-play CDN or decode failure stops playback and shows **Retry** (reloads the same server) and **Stream** — it does **not** silently switch to another server. **Anime** follows the same dead-cache path: a saved episode stream that expired no longer sticks on one failed row with an empty Source list — the full server list stays available and Forja re-searches from scratch
- Direct HTTP MP4/MKV/HLS opens use a browser-like User-Agent (and extractor Referer when provided). Pasting the same URL in Chrome is a close match; bare `libmpv` is not
- Seek preview needs a decodable frame; live or buffering streams may show time only
- Quality shows detected HLS variants. While **Auto** is active the menu hides Auto and highlights the resolution currently playing; pick a chip to lock that playlist (Auto reappears so you can unlock). Auto follows **Settings → Max stream quality** (soft mid-high ceiling when that setting is Auto; lock a higher chip or set 4K when you want the top rung). Single-quality or direct streams show the current decoded resolution (e.g. 1080p)
- On **Android** with ExoPlayer, recently played footage from a remote movie or episode is kept in a bounded on-device cache (and a short in-memory rewind window), so scrubbing back replays from storage instead of re-downloading. The cache is capped and evicts oldest-first, so it will not grow into your TV's storage. Torrent and local-proxy streams skip it — they already read from disk
- Long sessions benefit from [torrent cache settings](../settings/torrent-settings.md) when streaming magnets
